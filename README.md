# yeonchaking.github.io

이 문서는 "새 세션에서 다시 접속한 Codex/개발자"가 프로젝트 목적과 운영 기준을 즉시 복원하기 위한 운영 README다.

## 1) 프로젝트 목적 (Source of Truth)
- 이 저장소는 이직용 Android 포트폴리오 사이트다.
- 기술 데모 사이트가 아니라, 채용 담당자가 빠르게 판단할 수 있는 정보 전달이 목적이다.
- 우선순위는 아래 순서다.
1. 경력/성과 전달력
2. 가독성
3. 유지보수 용이성
4. 시각 커스터마이징

## 2) 작업 범위 (무엇을 유지/수정할지)
- 유지할 핵심 페이지
1. `index.md`: 단일 페이지 포트폴리오 (경력/프로젝트/기술 포함)
2. `_pages/404.md`: 기본 에러 페이지
- 유지할 핵심 설정
1. `_config.yml`: Jekyll/SEO/기본 메타
2. `_data/navigation.yml`: 상단 메뉴
3. `assets/css/main.scss`: 최소 스타일
4. `.github/workflows/jekyll.yml`: 배포 파이프라인
5. `작업기록.md`: 변경 이력 로그

## 3) 작업기록 운영 규칙
- 앞으로 모든 변경은 `작업기록.md`에 누적 등록한다.
- 최소 기록 단위
1. 작업 날짜
2. 변경 파일
3. 변경 이유
4. 사용자 영향(화면/배포/콘텐츠)
- 기능 수정/삭제/구조 변경은 반드시 기록한다.

## 4) 콘텐츠 편집 원칙
- 모든 문장은 "내가 무엇을 했다"보다 "무슨 문제를 어떻게 해결했고 결과가 무엇인지" 중심으로 쓴다.
- 가능하면 수치를 포함한다.
1. 기간 (예: 2024.07 ~ Present)
2. 규모 (사용자/디바이스/프로젝트 범위)
3. 성능/안정성 개선 수치

## 5) UI/스타일 원칙
- 과한 전역 스타일 금지
1. `!important` 남발 금지
2. 강한 배경색/저가독성 색조합 지양
- 목표는 "개성"보다 "전문성과 읽기 편함"
- 스타일은 `assets/css/main.scss` 한 곳에서 최소한으로 관리

## 6) 파일 추가/삭제 기준
- 새 파일 추가 전 체크
1. 채용 관점에서 실제 필요한가
2. 3개월 후에도 업데이트 가능한가
3. 메뉴 노출 가치가 있는가
- 아래 유형은 기본적으로 추가하지 않는다.
1. 샘플/더미 페이지
2. 실제로 쓰지 않는 archive/tag/category 페이지
3. 중복 설정 파일

## 7) 배포/실행 기준
- 배포 기준 브랜치: `main`
- 배포 방식: GitHub Actions (`.github/workflows/jekyll.yml`)
- 로컬 실행
```bash
bundle install
bundle exec jekyll serve
```
- 로컬 확인 주소: `http://127.0.0.1:4000`

## 8) 새 세션의 Codex에게 (작업 지시)
- 먼저 아래 파일을 읽고 시작한다.
1. `README.md`
2. `작업기록.md`
3. `_config.yml`
4. `index.md`
5. `_data/navigation.yml`
6. `assets/css/main.scss`
- 이후 작업은 다음 순서로 진행한다.
1. 목적 적합성 확인 (이직 포트폴리오에 필요한 변경인지)
2. 중복/불필요 코드 제거
3. 콘텐츠 가독성 개선
4. 스타일 최소 수정
5. `작업기록.md` 업데이트
- 큰 구조 변경 전에는 "왜 필요한지"를 짧게 남기고 진행한다.
